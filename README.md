# Тестовое задание Junior QA Engineer — «Квитто» (kvitto.pro)

Репозиторий с решением тестового задания на позицию Junior QA Engineer в компанию **Квитто** (`kvitto.pro`).  
Объект тестирования: демонстрационная страница оплаты курса (`https://kvitto-qa-demo.vercel.app`) и её REST API (`https://kvitto-qa-demo.vercel.app/api`).

## 2. Postman-коллекция (п. 4.3)

Файлы **`postman/Kvitto_API.postman_collection.json`** и **`postman/Kvitto_Env.postman_environment.json`**:
- Покрывают все 3 эндпоинта (`GET /api/tariffs`, `POST /api/payments`, `GET /api/payments/{id}`) позитивными и негативными сценариями.
- Все проверки реализованы через `pm.test` и `pm.expect`.
- Параметры вынесены в переменные окружения (`baseUrl`, `payment_id`). Активное окружение: **«Квитто QA Demo Environment»**.
- Добавлен Pre-request Script на уровне коллекции для генерации динамических данных покупателя (защита от коллизий).
- Запуск возможен в Postman через Collection Runner или из консоли через Newman:
```bash
npx newman run postman/Kvitto_API.postman_collection.json -e postman/Kvitto_Env.postman_environment.json
```

## 3. Резюме для продакт-менеджера (п. 4.4)

Подробное резюме вынесено в отдельный документ: [`summary_pm.md`](summary_pm.md).

> **Релизный вердикт:** Выпускать релиз в текущем виде **нельзя (категорически блокируется)**.
>
> **Топ-3 проблемы для первоочередного исправления:**
> 1. **BUG-08, BUG-09, BUG-14 (Ошибки в деньгах и скидках):** Списание на 3 000 ₽ больше заявленного на «Премиуме», обнуление цены до 0 ₽ при кликах по промокоду и игнорирование скидки бэкендом — прямой кассовый разрыв, скандалы с клиентами и риски судебных исков по ЗоЗПП.
> 2. **BUG-10, BUG-15 (Нарушение отправки чеков по 54-ФЗ):** Потеря поля `receipt_email` и перезапись его основным email — риск недоставки электронного чека покупателю и оборотных штрафов от ФНС по ст. 14.5 КоАП РФ.
> 3. **BUG-06, BUG-07 (Оплата без оферты и дублирование списаний):** Проведение платежа без согласия с офертой и политикой ПДн (штрафы Роскомнадзора), а также отсутствие блокировки кнопки «Оплатить», генерирующее повторные списания, чарджбэки и банковские комиссии.

## 4. Бонусные материалы (п. 5 ТЗ)

### Автотесты (Playwright + Pytest + Requests)
Расположены в каталоге `bonus/autotests/`:
- `test_api.py` — проверка контрактов API, статус-кодов и расчета скидок.
- `test_ui_form.py` — E2E тесты формы в Chromium: дефолтные значения, тариф «Премиум», рассрочка, промокод, оферта и адаптив 360 px.

```bash
pip install -r bonus/autotests/requirements.txt
playwright install chromium
pytest bonus/autotests/ -v
```

### Анализ безопасности API ([`bonus/security_audit.md`](bonus/security_audit.md))
- Подделка суммы платежа через декодирование Base64 ID (сервер принимает сгенерированную ссылку с суммой 1 ₽ без валидации).
- Падение сервера с кодом `500 Internal Server Error` при отсутствии обязательных полей (риск DoS).
- Создание платежей с несуществующим тарифом и суммой `amount: null`.

### Анализ адаптивности на 360 px и в Safari ([`bonus/responsive_audit.md`](bonus/responsive_audit.md))
- Локализована причина горизонтального скролла на 360 px из-за жесткого свойства `aside { min-width: 380px; }`.
- Проанализирована специфика WebKit: поведение `position: sticky` при появлении экранной клавиатуры и сглаживание шрифтов в iOS Safari.

### Анализ пробелов в спецификации ТЗ ([`bonus/spec_gap_critique.md`](bonus/spec_gap_critique.md))
- Описана необходимость заголовка `Idempotency-Key` для исключения задвоения транзакций на бэкенде.
- Сформированы требования к полной машине состояний платежа (`pending` → `authorized` → `succeeded` / `failed` / `refunded`).
- Выявлена необходимость серверных вебхуков, поддержки номеров СНГ (+77, +375) и обязательных ссылок на Оферту по 152-ФЗ.

### Исправленный прототип формы оплаты ([`fixed_site/index.html`](fixed_site/index.html))
Интерактивный прототип, демонстрирующий корректную работу всех требований ТЗ и устранение 8 фронтенд-дефектов (валидация, блокировка кнопки, оферта, расчет рассрочки, адаптив).
